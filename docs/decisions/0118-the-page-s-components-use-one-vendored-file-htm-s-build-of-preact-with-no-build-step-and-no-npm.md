# 0118. The page's components use one vendored file, htm's build of Preact, with no build step and no npm

- **Status:** Proposed
- **Date:** 2026-11-14

- The page's steps, forms and rounds of questions are components of one library: htm 3.1.1's `preact/standalone.module.js`, htm with the Preact 10 release and hooks its build bundled, one ES module of 13,194 bytes, 5.3 KB gzipped, that imports nothing. Components are written as htm's tagged templates, which htm parses at run time with an interpreter of its own, with no `eval` and no `new Function`, so the site plan's CSP, `script-src 'self' 'wasm-unsafe-eval'`, holds unchanged.
- The file is committed unchanged as `src/human_o_matic/web/static/js/vendor/htm-preact.js`, with the two licences it carries beside it, htm's Apache License 2.0 and Preact's MIT licence. Its version, the URL it was taken from and its SHA-256 are in `tools/build_site.toml`, and `tools/build_site.py` refuses to build when the committed file's SHA-256 differs. It is served from the site's own origin like the page's other files: no CDN, no import map, no `package.json`, no lockfile, no `node_modules` and no build step.
- The page's pure modules, the tabs' keyboard and ARIA state, the spring, the question count and the download's name, stay plain JavaScript that imports nothing from the library, so `node --test` runs them as before. Components pass no `style` as a string and use no `dangerouslySetInnerHTML`, which Preact writes through `cssText` and `innerHTML`; the spring writes `transform` and `opacity` through `element.style`.
- This amends [ADR 0112](0112-node-with-no-npm-package-runs-the-pyodide-test-and-the-page-s-pure-module-tests.md) only in that one vendored file joins Node and the pinned Pyodide in the page's JavaScript supply chain; no npm package is used. It is a fourth option in the site plan's comparison of frontends, and the one recommended.

**Why:** The page renders its state again on every answer: the steps, the request forms, the tabbed rounds and the Fine-tune sliders. Components keep that short and consistent where hand-written DOM updates grow with each form, and htm gives them without JSX's build step. One pinned file of 13 KB can be read whole and checked by its hash.

**Consequences:** `feat/web-ui` vendors the file, its licences and its pin. The scans for another origin allow XML namespace names, such as `http://www.w3.org/2000/svg`, which the file holds and no browser fetches. The bundled Preact is the one htm 3.1.1 was built with, published in April 2022, and the file doesn't state its exact version. Preact 11's hooks import `preact` by a bare name, which only an import map, an inline script the CSP refuses, or a build step would resolve, so a newer Preact needs a new htm release or a new decision.
