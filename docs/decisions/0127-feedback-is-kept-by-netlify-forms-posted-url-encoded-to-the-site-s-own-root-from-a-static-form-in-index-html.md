# 0127. Feedback is kept by Netlify Forms, posted URL-encoded to the site's own `/` from a static form in `index.html`

- **Status:** Accepted
- **Date:** 2026-11-15

- **The store** is Netlify Forms, the static host's own form service ([ADR 0099](0099-the-site-s-feedback-form-keeps-text-and-settings-never-midi.md) leaves the store to the site plan). The site has no server of its own: no web app, no Dockerfile and no new dependency. The server of the site's own stays the site plan's fallback, for when Netlify Forms can't be used.
- **The form Netlify reads** is the page's own, written in `index.html`, not drawn by script: `<form name="feedback" method="post" data-netlify="true" netlify-honeypot="bot-field">` with the site plan's six fields, `form-name` (hidden, `feedback`), `bot-field` (the honeypot, in an element hidden from people), `rating` (radios from 1 to 5, a choice required to send), `comment` (a textarea, `maxlength` 2,000), `contact` (`maxlength` 200) and `settings` (hidden). The build copies `index.html` as it is, so Netlify's form detection finds the form in the deployed page, though its step stays hidden until a download.
- **The post:** the page sends the form with `fetch("/", ...)`, `application/x-www-form-urlencoded`, the six fields and no other, built by `js/feedback.js` from the form's values and the settings, the comment and the contact cut to their limits, the honeypot as found, and the settings one field of JSON. It is the page's only request with a body. The CSP's `connect-src 'self'` already allows it, and nothing in the CSP changes.
- **Where it is asked:** step 8, Feedback, joins the top bar once a file is downloaded ([ADR 0121](0121-the-page-has-seven-steps-until-the-feedback-form-opens-the-song-afresh-for-each-kit-and-takes-the-next-seed-for-a-new-take.md)), from a "Next: Feedback" button beside "Download the file". The download reads `get_sections`, and the settings of that render are shown beside the form as they will be sent. A post the site refuses, or that gets no answer, says so and keeps what was written; one that is taken empties the form and thanks the user.
- **The notice** on the page's first step says that Netlify stores the feedback, records the sender's IP address with it and checks it for spam with Akismet, as ADR 0099 requires of a host's form service that records the address.

**Why:** Netlify Forms needs no code or server of the site's own, costs nothing on the existing account and comes with each deploy of the folder. Feedback kept by a third party with the sender's address is accepted, since the notice says so. A form written in the page is its own static copy, so the fields Netlify registers are the ones the page sends.

**Consequences:** Form detection has to be turned on for the site, and reads only deploys made after; whether it works on a dragged deploy is unverified, so the deploy runbook's test submission checks it. Netlify states no region or retention for submissions, and no rate limit: Akismet and the honeypot are the only brakes, and the page's limits hold only what the page itself sends. `build_site.py serve` takes no `POST`, so a send there says it wasn't sent.
