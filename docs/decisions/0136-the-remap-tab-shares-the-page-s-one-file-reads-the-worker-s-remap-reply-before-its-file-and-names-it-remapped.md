# 0136. The Remap tab shares the page's one file, reads the worker's `remap` reply before its file, and names it `-remapped-`

- **Status:** Accepted
- **Date:** 2026-11-16

- **The worker's call:** `remap` joins the worker's allowlist ([ADR 0114](0114-the-worker-api-takes-the-file-s-bytes-and-display-name-and-answers-an-error-as-error.md)). It takes the tool's arguments ([ADR 0133](0133-the-remap-tool-takes-paths-kits-and-every-answer-so-far-keeps-no-session-and-writes-one-file.md)) with `name`, the file's display name, for `midi_path`, the file's bytes beside it as `open_session` takes them, no `output_path` or `overwrite`, and `download`, false by default. It replies as the tool does, the file by its display name and no `output`, and with `download` set and every note placed, it gives the bytes the tool writes, both from `service.remap_reply`. It checks the browser's limits as `open_session` does, keeps no session and writes no file.
- **The tabs:** "Re-perform", shown when the page opens, and "Remap", in the ARIA tabs pattern: a `tablist` whose `tab`s name their `tabpanel`, the arrow keys, Home and End moving between them and showing the one reached. The step bar and "Last applied" show with Re-perform alone.
- **One file:** the page holds one file, which either tab's picker or drop zone chooses, and choosing one starts both tabs afresh. "Delete my file now" clears both, and starts again at Re-perform's step 1, as its words say.
- **The flow:** one card, with the file, then the kits as the Kits step asks them, the kit that plays it following the kit it came from until changed ([ADR 0121](0121-the-page-has-seven-steps-until-the-feedback-form-opens-the-song-afresh-for-each-kit-and-takes-the-next-seed-for-a-new-take.md)), and "Remap". The requests that came up show below, in the Check step's forms, and "Remap" sends again with every answer so far. Once every note is placed, the card says what to listen for, the conversion's lines as the Review step words them and the notes kept outside their velocity range, and "Download the file" takes the button's place. A kit or file changed drops the answers and starts the remap afresh.
- **The download:** `<name>-remapped-<n>.mid`, named as a re-performance's `<name>-humanized-<n>.mid` is, with `n` counting the visit's downloads from both tabs, and given by the same Blob URL ([ADR 0121](0121-the-page-has-seven-steps-until-the-feedback-form-opens-the-song-afresh-for-each-kit-and-takes-the-next-seed-for-a-new-take.md)).

**Why:** One function makes the tool's file and the page's, so the download is the tool's bytes. Reading the reply before the file lets the page say what changed before the download, as Review comes before Download. One file keeps "Delete my file now" deleting the one file the page holds, and lets a user change their mind about the tab without choosing the file again. A remapped file isn't humanized, so its name says what was done.

**Consequences:** The page asks the engine twice for a remap, once for its reply and once for its file. A user who deletes their file from the Remap tab returns to the Re-perform tab.
